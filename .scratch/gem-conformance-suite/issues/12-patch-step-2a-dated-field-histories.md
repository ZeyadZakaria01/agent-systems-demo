# 12: Patch step 2a: dated field histories and valid-time reads

**What to build:** The first part of commit 2 ("bitemporal field histories"). Field-history entries carry Zep's timestamps. Writes take optional `valid_from` / `invalid_at` and are ordered by valid time. An entry is valid until the next entry's `valid_from` unless it carries its own end, so an ordinary update stores no end date; keep-and-copy (ADR 0005, narrowed) runs only when a stored end date changes or a value is retracted. End-dated values and scoped overrides behave as the spec states. The default read returns the value valid now, hides expired entries unless history is requested, and returns `current` on every field. `valid_at` asks what was true on another date. With this, five of the six time probes flip on step 2 while C1 keeps passing. Recorded-time reads are ticket 13; chat is ticket 14. Spec: user stories 49, 51, 77, 78; Implementation Decisions "Patch, step 2" (entry model, writes, ordering and validity, corrections, end-dated values, scoped overrides, no LLM conflict check, queries); ADR 0005.

**Blocked by:** 03 (per-step runs), 09 (time probes), 21 (verdict rules and per-probe date detection)

**Status:** ready-for-agent

- [ ] The work lands as commit 2 on `bitemporal` with commit 1 untouched, and `patches/` is re-exported.
- [ ] Each history entry gains `invalid_at`, `created_at` and `expired_at` beside `valid_from`, plus `operation`, `replaces_entry_id` and `corrected_by_entry_id` where they apply.
- [ ] Undated writes behave as upstream: `valid_from` = `created_at` = write time, with no end. A `valid_from` that does not parse as a date keeps arrival order.
- [ ] Entries are ordered by `valid_from`; an entry is valid until the next entry's `valid_from` unless it carries its own `invalid_at`. A late-arriving older value ends where the later one begins, with no stored end. With equal `valid_from`, the later recorded entry wins.
- [ ] **An ordinary update stores no end date on the entry it replaces and does not expire or copy it.** One undated update leaves exactly two entries: C1's exact history check holds and upstream's `test_field_history_tools.py:27-49` (`history_count == 2`) passes unedited.
- [ ] Keep and copy runs only when a later write changes an entry's stored end date or retracts a value: the entry gets `expired_at` = now, and a corrected copy is appended with the original provenance, `operation: "interval_corrected"`, `replaces_entry_id` and `corrected_by_entry_id`. Copies count toward the 500-entry cap (a correction uses two entries).
- [ ] End-dated values stay current until their end. A write with `invalid_at` layers over the base value, and when several values are valid the shorter validity wins. A plain statement ends every value whose validity contains its `valid_from`, overrides included; ending an override that has a stored end changes that stored end, so keep-and-copy applies. Values in the same field compete with no LLM conflict check.
- [ ] The default `/v1/query` returns the value valid now and not expired. Expired entries are hidden unless history is requested (`explain`, temporal stages, `valid_at`); history reads show them with `expired_at`. `valid_at` selects the value true at that time, counts as a history request and raises salience like any read.
- [ ] **`current` on every field (`null` when nothing is valid) is returned on `/v1/query` and on `GET /api/ui/topics/{id}`.** The suite's adapter refuses the newest-entry fallback for a system that accepts dates (ticket 21), so a missing `current` raises an error.
- [ ] The server's OpenAPI schema declares each accepted date: `valid_from` and `invalid_at` on the write model, `valid_at` on the query model, so per-probe detection (ticket 21) finds them even if the patch names its models differently.
- [ ] Developer tests inside the patched copy cover ordering, the late older value, an ordinary update leaving exactly two entries, keep and copy only on a changed stored end or a retraction, expired entries hidden unless history is requested, the end-dated value, override layering and lapse, a plain statement ending an override, `valid_at`, `current: null` on `/v1/query` and the UI topic read, and the unparseable `valid_from`. Upstream's 39 tests pass unedited.
- [ ] Recorded run on step 2: T1, T2, T3, T4 (both stories, including the Oct 15 → $100 ask of story 2) and T6 pass with history intact, and C1 still passes. The case-level change table (ticket 23) shows those flips against step 1.
